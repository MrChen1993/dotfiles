# MISSION.md 格式

`MISSION.md` 在工作区根目录，记录用户学这个主题的**原因**。每一个教学决策——下一步教什么、推哪些资源、设计什么练习——都要能回溯到这份文档。

## 模板

```md
# Mission：{主题}

## 为什么（Why）
{1-3 句。用户追求的具体真实目标。掌握这项技能后，他的生活或工作会发生什么改变？避免「为了理解 X」这类抽象说法，逼出底层的真实结果。}

## 成功长什么样（Success looks like）
- {用户将能做到的、具体可观察的一件事}
- {另一件具体的事}
- {…}

## 约束（Constraints）
- {时间、预算、已有安排、学习偏好——任何会界定方法的东西}

## 不在范围内（Out of scope）
- {用户当前明确不想追的相邻主题——保护最近发展区}
```

## 规则

- **一个工作区一个 mission。** 想学两个不相关的东西 = 两个工作区。
- **具体压倒抽象。** 「十月前跑完半马」胜过「变得更健康」；「给团队交付一个 Rust CLI」胜过「学 Rust」。
- **对含糊要追问。** 如果用户说不清为什么，先访谈再动笔。坏的 mission 比没有 mission 更糟。
- **现实变了就修订。** Mission 会变。目标移动时更新本文件，别让陈旧的 mission 继续导航。
- **保持简短。** 如果 `MISSION.md` 超过一屏，它就从「指南针」变成「计划」了。

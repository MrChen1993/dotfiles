# PROFILE.md 格式

`PROFILE.md` 在工作区根目录，是**开局评测（Phase 0）的产物**——学习者画像。它是「课程定制」的地基：`MISSION.md` 回答「为什么学」，`PROFILE.md` 回答「这个人现在在哪、该从哪起、哪些能跳」。

## 模板

```md
# 学习者画像：{主题}

> 评测于 {日期} · 画像置信度：{高 / 中 / 低，做了校准题为高，仅靠自述为低}

## 现有水平
{一句话评级 + 依据。例：「中级——能用 Java 8 Stream 做常规转换，但对 Collector、并行流、惰性求值理解模糊（校准题第 2 题答错）。」}

## 学习起点（从这里开始教）
{具体到第一节课该切入的点。}

## 可以跳过的部分
- {用户已掌握、不必再教的点（自述 + 校准题验证过的）}
- {…}

## 重点攻克
- {落在最近发展区、最该花力气的点}
- {…}

## 节奏与投入
{每次想学多久、总周期、希望快还是稳。}

## 学习风格
{要不要讲原理、喜欢例子还是动手、能接受多大难度、其它偏好。与 NOTES.md 呼应。}
```

## 规则

- **一个工作区一份画像。** 学两个不相关的主题 = 两个工作区。
- **能跳过的要写明。** 「该跳过什么」和「该教什么」一样重要——这是定制感的直接来源，避免浪费用户时间在已会的内容上。
- **区分自述与实测。** 用户自述「我会 X」要标注；如果校准题验证过，置信度更高，可写进「可以跳过」。没验证过的存疑项，先教一个快速检查点再决定跳不跳。
- **随成长修订。** 后续课程中发现实际水平和画像不符，立刻更新本文件，并补一条 learning record 说明为什么变。画像是活的，不是一次性的。
- **保持简短。** 画像是「指南针」，不是「完整学习计划」。超过一屏就该精简。

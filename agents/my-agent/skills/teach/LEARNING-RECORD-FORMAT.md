# 学习记录格式

学习记录放在 `./learning-records/`，按序号命名：`0001-slug.md`、`0002-slug.md`……目录懒创建——写第一条时再建。

它们是教学版的 ADR：记录非显而易见的领悟、关键洞察、用户自述的已有基础。用来计算最近发展区。

## 模板

```md
# {一句话标题：学到了什么 / 确立了什么}

{1-3 句：学到了什么（或确立了什么已有基础），以及它为什么会影响后续教学。}
```

这就是全部格式。一条记录可以只是一段话。价值在于记下「**这件事现在已知了**」以及「**它为什么改变了下一步该教什么**」——而不在于填满各种小节。

## 可选小节（只在确有价值时加，多数记录用不上）

- **Status** 前置元数据（`active | superseded by LR-NNNN`）——当早先的理解被证明错误并被替代时有用。
- **Evidence**：用户如何证明了这个理解（答对了某题、完成了某练习、引用了过往经验）。当这个判断日后可能被重新审视时有用。
- **Implications**：这解锁了什么、排除了什么。非显而易见时值得记。

## 编号
扫描 `./learning-records/`，取最大序号加一。

## 什么时候写学习记录
满足任一条就写：
1. **用户真正理解了某个非平凡的东西**——不只是接触过，而是有证据表明他能正确使用这个概念。这抬高了「下一步该教什么」的地板。
2. **用户透露了已有基础**——「我已经会 X 了」。记下来，免得后续重复教。也记下他声称的深度。
3. **纠正了一个误区**——用户原先信了错的、现在明白为什么错。这类价值很高：它预示了相关主题上未来的绊脚石。
4. **mission 因学习而变了**——用户发现自己在意的其实是别的。交叉链接 [[MISSION.md]] 并更新它。

### 不算的情况
- 只是「讲过」的材料。讲过不等于学会。等到有证据再说。
- 已在 [[GLOSSARY.md]] 里简洁记过的术语定义。别重复。
- 逐次的活动流水账。学习记录不是日记，是决策级的洞察。

## 替代（Supersession）
当后来的记录推翻了早先的（用户理解加深或被纠正），把旧记录标 `Status: superseded by LR-NNNN`，而不是删掉。理解如何演进的历史本身就是有用信号。
